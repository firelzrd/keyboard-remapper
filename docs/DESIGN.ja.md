# 設計書: Keyboard Remapper(仮称)— Linux 向けキーボードリマッパー GUI

> ステータス: **実装済み(v0.1)**。末尾の「9. 実装メモ」に設計からの差分をまとめています。

## 1. 目的とゴール

- input-remapper 2 と同等の「キー / キー組み合わせ → 機能」の割当を GUI で行えるアプリ。
- 接続中のキーボードを **実物に近い見た目で描画**し、キーをクリックする/実際に押すだけで割当を確認・変更できる。
- **input-remapper 2 の「修飾キー+通常キーで一瞬カクッと止まる」不具合を構造的に起こさない**。
- 日本語環境(JIS 109 配列、日本語 UI)を一級市民として扱う。

対象外(初版): マウス/ゲームパッドのリマップ、コマンド実行アクション(→ F13〜F24 に割当て DE のショートカットで代替できるよう案内)。

## 2. カクつき問題の原因と対策(最重要)

### 原因
input-remapper 2 は出力に **2 種類の仮想デバイス**を使います。

| 出力 | 仮想デバイス |
|---|---|
| 割当なしでそのまま通すキー(Ctrl 等) | `input-remapper <機器名> forwarded` |
| 割当によって生成したキー | `input-remapper keyboard` |

X サーバ(および XWayland)は、キー入力の発生元 *スレーブデバイス* が切り替わるたびに
その機器のキーマップをマスターキーボードへコピーし、`XkbNewKeyboardNotify` / `MappingNotify`
を全クライアントへ送ります。GNOME Shell / KWin などはこれを受けて **全グローバルショートカットを
再グラブ**するため、数十〜数百 ms 固まります。
「Ctrl(forwarded から出る)→ 割当キー(keyboard から出る)」や、その逆順はまさに
毎回デバイスが切り替わるパターンで、これがカクつきの正体です。

### 対策
1. **出力用の仮想デバイスを 1 つだけ**作り、素通しのキーも割当で生成したキーも、
   全て同じデバイスから出す。→ 発生元が切り替わらないので再登録が起きない。
2. その仮想デバイスは**デーモン起動時に 1 度だけ作成し、プリセット適用/変更/停止で作り直さない**
   (デバイスの出現・消滅自体も DE に再設定を引き起こすため)。
3. 能力(capabilities)は全キーボードキーを最初から宣言しておき、後から変化させない。
4. 同じ物理キーボードの兄弟ノード(例: `... Keyboard` と `... Consumer Control`)は
   まとめて grab し、同じ仮想デバイスへ出力する(メディアキー経由の切替も防ぐ)。
5. 複数キーボードにプリセットを適用しても、出力は同じ 1 台の仮想デバイスに集約する。

これを自動テストで保証する(「どんな入力列でも出力先デバイスは常に 1 つ」「適用/変更で仮想デバイスが再生成されない」)。

## 3. 全体構成

```
┌─────────────────────────┐   JSON over Unix socket   ┌──────────────────────────────┐
│ GUI (ユーザー権限)      │ ────────────────────────▶ │ keyboard-remapperd (root/systemd) │
│ GTK4 + libadwaita       │ ◀──── キーイベント配信 ─── │  ・デバイス列挙/ホットプラグ    │
│  ・キーボード描画       │                           │  ・evdev grab                 │
│  ・割当編集/自動保存    │                           │  ・Engine(変換ロジック)       │
└─────────────────────────┘                           │  ・単一 uinput 仮想キーボード  │
        ▲                                             │  ・LED(Caps/Num)の逆伝搬     │
        │ ~/.config/keyboard-remapper/ (プリセット JSON)        └──────────────────────────────┘
┌─────────────────────────┐
│ keyboard-remapper-ctl (CLI)  │  ログイン時 autoload / スクリプト用
└─────────────────────────┘
```

| モジュール | 役割 |
|---|---|
| `keyboard_remapper/keys.py` | キーコード、表示名(英/日)、修飾キー定義 |
| `keyboard_remapper/layouts.py` | 物理配列ジオメトリ(ANSI / ISO / JIS × フル / TKL / 75%) |
| `keyboard_remapper/mapping.py` | プリセット/割当のデータモデル、JSON 入出力、競合検出 |
| `keyboard_remapper/engine.py` | 入力→出力の状態機械(純粋ロジック、デバイス非依存で単体テスト可能) |
| `keyboard_remapper/daemon.py` | asyncio デーモン。evdev 入力・uinput 出力・IPC サーバ |
| `keyboard_remapper/ipc.py` | プロトコルとクライアント |
| `keyboard_remapper/config.py` | 設定・プリセット保存、autoload 設定 |
| `keyboard_remapper/gui/` | アプリ本体、キーボードウィジェット、エディタ、キー選択ポップオーバー |
| `data/` | systemd unit、.desktop、autostart、polkit、アイコン |
| `tests/` | エンジン/モデル/配列/IPC のテスト、GUI スモークテスト |

UI ライブラリは **GTK4 + libadwaita(PyGObject)**。GNOME の現行デザイン言語に沿い、
ライト/ダーク自動追従、HiDPI、Wayland/X11 両対応。

## 4. 変換エンジンの仕様

### 割当のモデル
```jsonc
{
  "name": "Default",
  "mappings": [
    { "trigger": ["CapsLock"],          "action": {"type": "key",      "output": ["Ctrl"]} },
    { "trigger": ["Ctrl", "J"],         "action": {"type": "key",      "output": ["Down"]} },
    { "trigger": ["Super", "E"],        "action": {"type": "sequence", "steps": ["Ctrl+C", "wait 50", "Ctrl+V"]} },
    { "trigger": ["Ctrl", "Q"],         "action": {"type": "disable"} }
  ]
}
```
- **トリガー** = 「押しっぱなしのキー群 + 最後に押すキー」。最後のキー以外は順不同。
- 修飾キーは既定で **左右どちらでも可**(`Ctrl`)。チップをクリックで `左Ctrl` / `右Ctrl` に限定可能。
- **アクション**: `key`(単キー/ショートカット出力)、`sequence`(連続入力+待機)、`disable`(無効化)。

### 動作
- 割当のないキーは即座に素通し(Ctrl+クリック等が壊れないよう、修飾キーを遅延させない)。
- 最後のキーが押された時、保持中キーを満たす割当のうち**最も具体的なもの**を選ぶ。
- 発火時、トリガーに含まれる修飾キーが既に出力済みなら一時的に離す(出力側で同じ修飾が必要なら離さない)。
- その際、**修飾キーの「単押し」誤検出を防ぐガード**を挿入(Super 単押しで GNOME のアクティビティが開く、
  Alt 単押しでメニューが開く、を回避)。
- 一時的に離した修飾キーは、ユーザーがまだ押していて **次に別のキーを押した時に**だけ押し直す(遅延復元)。
  → Ctrl を押したまま J を連打 → 下移動を連打、その後 C で Ctrl+C、が自然に動き、無駄な修飾キーの上下も出ない。
- トリガー外の修飾キーはそのまま有効(例: `Ctrl+J → ↓` 中に Shift も押せば Shift+↓ = 範囲選択)。
- 出力はキーごとに参照カウント管理(複数の入力が同じ出力を押しても正しく離れる)。
- 停止/プリセット変更/デバイス切断時は押下中の出力を全て離す(キー押しっぱなし事故の防止)。
- Caps Lock 等の LED は仮想デバイス → 物理キーボードへ反映。

## 5. GUI 設計

```
┌ [⌨ HHKB Professional ▾]      Keyboard Remapper — 適用中: 「仕事用」      [プリセット ▾] [● 有効] [☰] ┐
├──────────────────────────────────────────────────────────────────────────┬─────────────────┤
│  レイヤー: (基本) [Ctrl] [Shift] [Alt] [Super]        配列: JIS・フル ▾  │ 割当一覧  🔍 ＋ │
│ ┌──────────────────────────────────────────────────────────────────────┐ │ CapsLock → Ctrl │
│ │  Esc  F1 F2 …                                                        │ │ Ctrl+J  → ↓     │
│ │  半/全 1  2  3 …        ← キーキャップを立体的に描画                    │ │ Ctrl+K  → ↑     │
│ │  Tab  Q  W  E …            割当済みキーはアクセント色+「→ 出力」を表示  │ │ Super+E → 連続  │
│ │  Caps→Ctrl  A …            選択キーはリング、実際に押したキーは沈み込む  │ │ Ctrl+Q  → 無効  │
│ └──────────────────────────────────────────────────────────────────────┘ │                 │
│ ┌ 選択中: [Ctrl] + [J]   (⏺ 録画で変更)  ──────────────────────────────┐ │                 │
│ │ 動作: (● キー/ショートカット) ( 連続入力 ) ( 無効化 )  [割当を削除]     │ │                 │
│ │ 出力: [↓ Down]   [⏺ 押して指定] [一覧から選ぶ…]                       │ │                 │
│ └──────────────────────────────────────────────────────────────────────┘ │                 │
└──────────────────────────────────────────────────────────────────────────┴─────────────────┘
```

操作の流れ(「迷わない」ことを最優先):
1. **キーをクリック**するか、**実際にキー(組み合わせ)を押す**とそのキーが選択される。
   Ctrl を押しっぱなしにすると画面のキーボードが Ctrl レイヤー表示に切り替わり、
   各キーに「Ctrl+そのキー」の割当が見える。
2. 下のエディタで動作と出力を選ぶ。出力は「押して指定」「一覧から検索(メディアキー、F13〜F24 等も含む)」
   「画面のキーボードをクリック」のいずれでも指定可能。
3. **変更は自動保存**。プリセット適用中なら即座にデーモンへ反映(保存ボタン・再適用不要)。
   削除時はトーストで「元に戻す」。
4. ヘッダーの **有効スイッチ** でそのキーボードへの適用 ON/OFF。ログイン時の自動適用もここで設定。

その他:
- 配列(ANSI / ISO / JIS、フル / TKL / 75%)はデバイスごとに記憶。初期値はシステムの XKB 設定・
  ロケールから推定(日本語環境なら JIS)。
- 配列上に存在しないキー(メディアキー等)の割当は、キーボード下の「その他のキー」行に表示。
- 録画中はデーモンがキーボードを一時的に排他取得し、Super や Alt+F4 などが DE に届かないようにする
  (ポインタ操作でキャンセル可、タイムアウトで必ず解放)。
- 競合(同じトリガーの重複)はリスト上で警告表示。
- UI は日本語/英語(ロケールで自動切替)。キー名も日本語表記(半角/全角、変換、無変換、かな 等)。
- デーモン未起動時はバナーで案内し、ボタン 1 つで `pkexec` 起動。未起動でも編集は可能。

## 6. 権限とセキュリティ

- デーモンは root(systemd)で動作し、`/run/keyboard-remapper/socket` で待受。
- キー入力を配信できる=キーロガーになり得るため、接続元を `SO_PEERCRED` で検証し、
  root または **ログイン中のアクティブなローカルセッションのユーザー**のみ許可。
- プリセットはユーザーの `~/.config/keyboard-remapper/` に保存。適用時に内容をデーモンへ送る。
  デーモンは適用状態を `/var/lib/keyboard-remapper/` に保持し、再起動・再接続時に自動復元。

## 7. テスト計画

- **エンジン単体テスト**: 単キー、組み合わせ(修飾→通常、通常→修飾の逆順)、修飾キーの一時解放と遅延復元、
  単押しガード、参照カウント、連続入力、無効化、全解放、オートリピート。
- **カクつき対策の回帰テスト**: 全出力が単一の仮想デバイスから出ること、プリセット適用/変更/停止で
  仮想デバイスが再生成されないこと。
- **デーモン/IPC テスト**: 偽デバイスバックエンドでデバイス列挙・適用・録画・配信。
- **GUI テスト**: Xvfb 上で起動し、偽デーモンに接続してクリック/キー入力/割当編集を操作、
  スクリーンショットで見た目(ライト/ダーク、JIS/ANSI、ウィンドウ幅)を確認しながら改良を繰り返す。

## 8. 決めていただきたい点

1. **アプリ名**: 仮に「Keyboard Remapper」(コマンド `keyboard-remapper` / `keyboard-remapperd` / `keyboard-remapper-ctl`)。
2. **初版のアクション範囲**: キー/ショートカット、連続入力、無効化 の 3 種で良いか。
   (コマンド実行・文字列入力・マウスボタン出力は後回しの想定)
3. **組み合わせの順序**: 「最後のキー以外は順不同、最後のキーで発火」(一般的なショートカットと同じ)で良いか。
   input-remapper のような「どの順で押しても発火」も選べるようにするか。
4. **「実際に押したキーを自動選択」** を既定で ON にするか(便利だが、適用中は押したキーの出力も DE に届く)。

## 9. 実装メモ(設計からの差分と、設計後に決めたこと)

決定事項(§8)は既定どおり: 名前は Keyboard Remapper、アクションは 3 種、「最後のキーで発火」、キーの自動選択は ON。

| 項目 | 設計 | 実装 |
|---|---|---|
| プリセット | 複数プリセットの切替 | **キーボードごとに 1 セット**(初版)。複数プリセット/書き出しは今後 |
| 配列 | ANSI/ISO/JIS × フル/TKL/75% | ANSI/ISO/JIS × フル/TKL(75% は今後) |
| 「どの順でも発火」モード | 検討 | **見送り**。逆順(通常キー→修飾キー)を遅延なしで通すため、発火は常に最後のキー |
| 組み合わせの照合 | 物理キー | **物理キー + 「単一キーに割り当て済みのキー」の出力**。`CapsLock→Ctrl` にして `Ctrl+J→↓` を定義すると、CapsLock+J で ↓ になる(Caps/Ctrl 入れ替えの定番設定を素直に動かすため) |
| 修飾キーの隠し方 | 一時的に離して遅延復元 | 設計どおり。Super/Alt を隠す時は無害なキー(F24)を挟んで単独押し扱いを回避 |
| 自動リピート | — | 入力側のリピート(value=2)は捨て、出力は押下状態のみ。リピートはデスクトップ側が行う |
| 録画 | デーモンが排他取得 | 設計どおり。デーモン未接続時は GTK のキーイベントで代替(evdev コード = keycode − 8) |
| デーモン未接続 | バナー+起動ボタン | 加えて、設定に記憶済みのキーボードは**オフラインでも編集可能**。接続後に自動反映 |
| 起動時の取り込み | — | キーが押されている間は取り込まない(押下中に取り込むと、離した時のイベントがデスクトップに届かず**キーが押しっぱなし**になるため) |
| 追加 | — | `--grab-all`: 割り当てのないキーボードも同じ仮想デバイスに集約(複数キーボードを交互に使っても入力元が切り替わらない) |

### テスト
- `tests/test_engine*.py`: 変換ロジック(修飾キーの隠蔽/遅延復元/連打、逆順、Super ガード、連続入力、
  ランダム入力 300 パターンでの「押しっぱなしが残らない・二重押下が無い」検証)
- `tests/test_daemon.py`: 偽デバイスでのデーモン/IPC。**出力用の仮想デバイスが常に 1 台だけで、
  適用・停止・録画・ホットプラグを繰り返しても再作成されない**ことを検証(カクつき対策の回帰テスト)
- `tests/test_gui.py`: Xvfb 上の実ウィンドウ + 偽デーモンで、選択・割り当て作成・録画・自動保存・
  デーモン切断などの操作を検証

### 未検証の点
開発環境に `/dev/uinput` と実キーボードが無かったため、**実機の evdev / uinput 経路
(`keyboard_remapper/backend.py` の `Evdev*`)と、実デスクトップ上でカクつきが消えること**は未確認です。
ロジックは偽バックエンドで検証済みで、実機層は薄く作ってあります。
